FixedlowR1-PGS-015Pages and routes

Uppercase project, area and developer addresses do not serve a second page

Expected: 404 with Page not found. Slugs are lowercase only, so a second copy of the page at another address is a bug.

Actual: GET /projects/FLORA-BAY-RESIDENCES -> 308 (30 bytes)

Root cause: Next.js matches prerendered dynamic paths case-insensitively on the first request; the data lookup is case-sensitive, so the answer changed once cached. Only the canonical tag prevented a duplicate-content page.

Fix: none: the repository has no remote yet (local commit only) fix/qa-r1-2026-11-02

Note: If the team later prefers a 308 to lowercase, change expectStatus and redirectTo. The rule is one canonical address. First run failed because the probe was wrong (test-design error, not a product bug): the first run showed the real product bug (uppercase address served the page on first visit); expectation widened to 404 or a permanent redirect to the lowercase address. Probe corrected and rerun. Case designed by Haiku; executed by Sonnet (qa/run.mjs).
